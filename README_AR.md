يبحث قسم الشباب عن الهوديز وملابس الشارع والزوايا الخلفية/الجانبية. ثلاثة مواضيع للصور بالأبيض والأسود وموضوع للمدينة ليلًا. البحث والمفاضلة يعتمدان على وصف المصدر ووسومه ومتوسط لون الصورة؛ لا يوجد ضمان للتطابق الدلالي أو هوية الشخص أو جودة التصنيف بصريًا بنسبة 100%.

**عرض Unsplash:** تُستخدم روابط الصور الأصلية كما أعادها API، مع البنر كصورة كبيرة والأفتار كصورة جانبية. لا تُحمّل هذه الصور في مكتبة ملفات محلية ولا تُرفع كصورة مركبة إلى Discord. هذا يختلف عن البطاقة المركبة للصور التي يرفعها المشرف بنفسه ولصور الأفلام. نسبة كل صورة إلى مصورها ورابط Unsplash تظهر في المنشور.

## إعداد الاستضافة

1. فك الضغط في جذر البوت؛ يجب أن يوجد `index.js` و`package.json` في الجذر. احتفظ بنسخة احتياطية من `.env` و`storage/` إذا كنت تحدث إصدارًا قديمًا.
2. استخدم **Node.js 22.12 أو أحدث**.
3. انسخ `.env.example` إلى `.env` وأدخل القيم. عند الترقية، حدّث إعدادات ملفك الموجود بدل الكتابة فوق مفاتيحك.
4. الإعدادات المطلوبة:
   - `DISCORD_TOKEN`: توكن البوت من Discord Developer Portal.
   - `UNSPLASH_ACCESS_KEY`: **Access Key** من تطبيقك في Unsplash Developers؛ ليس Secret Key.
   - `FANART_API_KEY`: مفتاح API/Project من Fanart.tv لجلب الأفلام.
   - `GUILD_ID`: معرف السيرفر، اختياري لتسجيل الأوامر في سيرفر واحد مباشرة. اتركه فارغًا للتسجيل العالمي.
   - `FANART_MOVIE_IDS`: معرفات IMDb مفصولة بفواصل. توجد قائمة افتراضية، ولا تعني توفر الأفلام على Netflix أو ملاءمتها لجميع الأعمار.
   - `WALLHAVEN_API_KEY`: اختياري؛ البحث العام الآمن لا يحتاج مفتاحًا.
5. ثبّت وشغّل:
   ```sh
   npm install
   npm run check
   npm test
   npm start
   ```
6. ادعُ البوت باختيارات `bot` و`applications.commands`. يحتاج عرض الرومات وإرسال الرسائل وEmbed Links وقراءة سجل الرسائل؛ والأطقم المحلية تحتاج Attach Files. أمر إنشاء الرومات يحتاج Manage Channels. فعّل Message Content Intent فقط إذا فعّلت استيراد رومات صور المشرفين.
7. استخدم `/تجهيز-الرومات` أو `/ربط-روم`، ثم `/جلب-صور` و`/نشر-الآن` للتحقق من كل قسم و`/حالة` لعرض الخطأ إذا ظهر.

لا تُرسل التوكن أو المفاتيح في المحادثة. الملف المضغوط لا يتضمن مفاتيح حقيقية. راجع `SETUP_KEYS_AR.md` للحصول على خطوات المفاتيح.

## النشر التلقائي

`AUTO_FETCH=true` يفعّل جلب أطقم Unsplash والأفلام. `WALLHAVEN_ENABLED=true` يفعّل معاينات الأنمي وPC.

الفاصل الافتراضي لكل روم **40 دقيقة**، ويمكن تغييره من `/مدة-النشر`. يفحص البوت الرومات كل 20 ثانية، وأول فحص بعد 5 ثوانٍ من جاهزيته واستعادة سجل النشر. النشر يحصل عند حلول موعد الروم؛ تشغيل البوت وحده لا ينشئ رومات أو يربطها تلقائيًا.

عند SOURCE_ONLY=false فقط، يفحص الجلب الخلفي قسم أطقم واحدًا كل5دقائق. الوضع الافتراضي SOURCE_ONLY=true يجلب عند النشر مباشرة. `IMAGE_FETCH_INTERVAL_MINUTES=80` يحدد مهلة الجلب الخلفي لكل قسم، لكن نفاد أطقم روم مستحق يسمح بجلب طقم جديد عند الطلب. الأخطاء والنتائج الفارغة لها انتظار قصير، وحد API قد يفرض انتظارًا أطول. لا تُحسب الرسالة منشورة إذا رفض Discord إرسالها.

لا يُعاد نشر الطقم نفسه بعد نفاد المكتبة، ولا تُخلط الأقسام. يسجل البوت معرفات المصدر لمنع إعادة استخدام الصورة نفسها كأفتار أو بانر داخل المكتبة. إذا لم يجد صورًا مناسبة، يتجاوز النشر ويعرض السبب بدل إرسال صور من قسم آخر.

## Unsplash وحدود الطلبات

- طلبات البحث تستخدم Client-ID ومفتاح Access Key في الترويسة؛ الصور نفسها تظهر بروابط images.unsplash.com دون تمرير بيانات المصادقة إليها.
- تُحفظ بيانات البحث لمدة ساعة لتقليل الطلبات؛ لا تُحفظ ملفات الصور أو المفتاح كنص واضح في الذاكرة المؤقتة.
- يوجد حد محلي محافظ يبلغ 45 طلب API في الساعة لكل مفتاح، يشمل البحث وتسجيل استخدام الصور، مع احترام إشارات نفاد الحصة القادمة من الخدمة. الحسابات التجريبية تُعرف عادة بحد 50 طلبًا/ساعة؛ تحقق من حد تطبيقك داخل Unsplash لأنه قد يختلف.
- يُسجل استخدام الصورتين عند اختيار الطقم للنشر أو طلب تنزيله؛ البحث والمعاينة لا يسجلان المرشحين غير المختارين كتنزيلات.
- البحث عن الأبيض والأسود يستعمل فلتر المصدر. فحص التناسق يستعمل متوسط اللون الذي يعيده Unsplash، ولا يفحص بكسلات الصورة. البطاقة المركبة للصور المحلية تستمر في استعمال sharp وفحوص الجودة المحلية.
- يحتاج المزيد من السيرفرات/الرومات إلى حصة API مناسبة؛ لا توجد ضمانات بعدد غير محدود من الصور أو الطلبات.

## الأوامر

- `/لوحة-التحكم`: القائمة العربية.
- `/جلب-صور`: إضافة طقم من Unsplash أو Fanart.tv، أو استكشاف رابط Wallhaven.
- `/عرض-الصور` و`/معاينة`: الأطقم المتاحة، بما فيها روابط Unsplash. معاينات Wallhaven المنشورة مباشرة لا تدخل مكتبة الأطقم.
- `/مصادر`: المصادر وروابطها.
- `/حالة`: حالة الرومات ووجود المفاتيح وآخر أخطاء المصادر. وجود المفتاح لا يثبت صلاحيته.
- `/مدة-النشر` و`/تشغيل-روم` و`/إيقاف-روم`: التحكم بكل روم مستقلًا.
- `/إضافة-صورة`: أفتار وبنر محليان مختلفان ومتناسقان، أو صورة أفقية واحدة لـPC. أكّد نوع الصورة عند طلبه وأضف رابط الفيلم لقسم الأفلام.
- `/استيراد-حسابي`: استيراد أفتارك وبنرك أنت فقط بعد تأكيد التصنيف.
- `/مصدر-صور`: تعيين روم صور المشرفين عند تفعيل `ENABLE_SOURCE_CHANNELS=true`.
- `/مجموعات-4k`: روابط صفحات مجموعات خلفيات فقط؛ ليس مصدر جلب آلي.

## الترقية والمكتبة القديمة

أزيلت مسارات الجلب من Pexels وPixabay، ولا يحتاج الإصدار إلى مفاتيحهما. تبقى الأطقم المؤهلة التي سبق تنزيلها من هذين المصدرين محفوظة وقابلة للنشر. صور الشباب العامة المرفقة والمستوردة تلقائيًا قبل تحديث الستايل تبقى محفوظة لكنها مستبعدة، وصور المشرفين المراجعة تبقى متاحة.

Openverse وWikimedia وTMDB لا تُستخدم في الجلب. سجلاتها القديمة محفوظة للنسخ الاحتياطي ومستبعدة من النشر. احفظ `storage/` للاحتفاظ بالرومات وسجل الاستخدام والأطقم وبيانات المصدر المؤقتة.

المثال `examples/BOT_MESSAGE_EXAMPLE.png` يعرض البطاقة المحلية القديمة فقط، وليس شكل Embed Unsplash أو نتيجة جلب حي حديث.

تحتاج الاستضافة HTTPS إلى `api.unsplash.com` و`images.unsplash.com` وDiscord وخوادمه، و`webservice.fanart.tv` و`assets.fanart.tv` و`wallhaven.cc` و`th.wallhaven.cc`؛ التثبيت يحتاج مستودع npm.

فُحص JavaScript و24 مجموعة اختبار محلية، تشمل المؤقتات الفعلية والجلب والنشر للأقسام الخمسة بردود مصادر وDiscord محاكاة. تتحقق الاختبارات من روابط Unsplash ونسبة المصورين وتسجيل الاستخدام ومنع إعادة رفع الصور، ومعالجة الأفلام المحلية وسلامة الرومات والمواعيد والأخطاء.

لم يُختبر تسجيل الدخول إلى Discord أو الجلب الحي بمفتاح Unsplash في هذه البيئة، ولا إصدار حساب أو مفتاح جديد. الوصول إلى توثيق الموقع المباشر رفضته سياسة الشبكة؛ روجعت متطلبات الدمج من مستودع SDK الرسمي. يلزم إدخال القيم الصحيحة على الاستضافة وإجراء التحقق الحي هناك.

- تأكيد حذف المنشور يُقر التفاعل قبل عمليات الشبكة، وأخطاء الإكمال التلقائي تُعالج برد مناسب لنوع التفاعل.
- عند تفعيل ENABLE_SOURCE_CHANNELS، يعد رفع عضو يملك Manage Server صورًا في روم مصدر مضبوط إقرارًا بمراجعتها وتصنيفها. استيراد الشباب والبنات والأنمي يعمل من تلك الرومات؛ استيراد الأفلام يتطلب أيضًا رابط HTTPS للمصدر داخل الرسالة. الميزة ما زالت متوقفة افتراضيًا.
- جلب صور Fanart لا يكرر تنزيل الرابط نفسه داخل المحاولة، ويُظهر فشل تنزيل الصور كخطأ مصدر بدل اعتباره نفادًا للنتائج.

## النشر من المواقع فقط — V16.6

SOURCE_ONLY=true هو الافتراضي حتى لو لم يكن السطر موجودًا في .env القديم. يطلب كل نشر طقمًا جديدًا من المصدر؛ لا يختار أطقم المكتبة المرفقة أو صور المشرفين أو أطقم المصدر المحفوظة سابقًا. عند الخطأ أو عدم وجود نتيجة مناسبة يتجاوز النشر ويظهر السبب، دون الرجوع للمكتبة.

في هذا الوضع يتوقف الجلب الخلفي الذي كان يملأ المكتبة، ويتم الجلب عند موعد النشر. يسمح API باستخدام بيانات بحث مؤقتة لتقليل الطلبات؛ الصور المختارة جديدة غير مستخدمة من نتائج المصدر، وليس من صور المكتبة المحلية. لمعرفة الوضع راجع /حالة.

الأنمي يجلب أفتارًا رأسيًا/مربعًا وبنرًا أفقيًا من Wallhaven ضمن موضوع واحد مثل ساكورا أو ليل أو سماء. يحمل الصورتين الأصليتين، ويتحقق من اختلافهما وأبعادهما وتشابه ألوانهما، ثم يرسم البطاقة المركبة. لا تعني مطابقة الموضوع والألوان أن الشخص نفسه يظهر في الصورتين؛ النتائج غير المتناسقة تُرفض بدل جمع صورتين عشوائيتين. الصور تبقى لأصحابها وتظهر روابط المصدر.

أبقِ SOURCE_ONLY=true وAUTO_FETCH=true وWALLHAVEN_ENABLED=true. إعداد SOURCE_ONLY=false يعيد وضع المكتبة القديم فقط إذا رغبت به صراحة. النشر من Unsplash يبقى بصور المصدر الأصلية وبنر كبير وأفتار جانبي وفق متطلبات API، وخلفيات PC تظل صورة أفقية واحدة.

## توافق صور الأفلام V16.7.1

إذا أعاد Fanart رابط صورة قديمًا بصيغة HTTP على assets.fanart.tv، يحوله البوت إلى HTTPS قبل التنزيل مع فحص المضيف والمسار. لا تُقبل روابط مضيف آخر أو بيانات دخول داخل الرابط أو منافذ غير معتادة.

إذا بقي قسم movies متوقفًا، شغّل /جلب-صور واختر movies وراجع /حالة: غياب FANART_API_KEY أو خطأ401/403 يحتاج تحققًا من مفتاح المشروع، وفشل تنزيل الصور يحتاج وصولًا إلى assets.fanart.tv. قائمة الأفلام مضبوطة في FANART_MOVIE_IDS؛ يمكن جلب أطقم أخرى للفيلم نفسه ما دامت صور الأفتار والبنر لم تستعمل سابقًا. إذا استنفدت صور الأفلام، أضف معرفات أخرى إلى القائمة. الاختبارات المحلية لا تثبت صلاحية مفتاح المستخدم أو الاتصال من استضافته.

نجح `npm run check` و`npm test` (24مجموعة). فُحصت ردود Discord الفعلية من ناحية تركيب الرسائل، والتلقائي والمواعيد والتوقف والتكرار والمصادر ببيانات محاكاة. لا تعني هذه النتيجة ضمان خلو البرنامج من كل خطأ أو التحقق من اتصال استضافتك بالخدمات.
